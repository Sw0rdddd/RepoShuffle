# 局限性

以下基于 [0.3.1 真实仓库测评](evaluation-0.3.1.md)。转换和静态检查成功，不等于运行行为完全兼容。

## 已知兼容性问题

| 场景 | 观察结果 |
| --- | --- |
| 静态模块查找、按源码路径推导模块 | Astroid 在 flat/random 下分别新增 8/7 个失败；原版已有的 5 个失败不计入新增。 |
| 依赖物理模块身份或目录扫描 | Boltons random 额外收集 5 个测试节点，缓存键的物理模块身份、目录遍历 doctest 各失败 1 项；flat 结果与原版一致。 |
| 直接遍历并加载物理源码 | SymPy 绕过逻辑路由、重复加载实现，影响类型和单例身份，flat/random 分别出现 53/60 个失败。 |

依赖实际文件位置、物理模块身份或源码扫描的项目，需要单独验证；这些问题未在本轮修复，也未通过修改上游断言规避。

## 未能验证的范围

- Pydantic 原版和两种转换版均发生 Windows 原生栈溢出（退出码 `3221225725`）；单独运行类型测试也在另一用例崩溃。无完整 JUnit 结果，不能认定通过或功能等价，也不能将崩溃归因于转换。
- 测评仅覆盖所列 Windows 环境和测试子集，不包含完整框架测试、未安装的可选后端及其他平台。
- 工具测试中的符号链接用例因 Windows 权限跳过，未在本环境验证。

## 布局复现边界

同版本、相同输入和参数可复现布局；当前布局版本为 4，不承诺复现布局版本 3 的输出。清单 schema 仍为 3。
