# 局限性

以下基于 [0.3.2 当前测试集](evaluation-0.3.2.md)。`plan.ok` 只表示静态检查未发现阻塞项；`plan.compatibility` 的构建适配和风险报告不是运行等价证明。

## 当前测评中的失败

| 场景 | 实测结果 |
| --- | --- |
| 严格限制包导入时允许加载的标准库 | Click 两种模式各有 1 个 `test_light_imports` 失败：模块路由需要额外标准库，超出上游轻量导入白名单。 |
| 对物理目录内容作固定断言 | Boltons random 有 1 个目录遍历 doctest 失败；逻辑模块别名不能恢复原来的文件分组。 |

不通过保留整个实现区、修改白名单或排除这些测试来掩盖限制。

## 适用边界

- 普通物理模块导入可复用逻辑模块身份；显式 `SourceFileLoader`、`exec` 或自定义加载器仍可能绕过路由。
- 文件与回溯路径会变化。位置锚点按需保留，但路径分析不是完整 Python 解释器，无法穷尽动态表达式或外部路径。
- setuptools、Poetry、Hatch、Flit 有针对性构建验证；自定义后端、精确文件排除、特殊编译流程和静态类型解析仍需独立验证。Flit 按单包边界放置实现。
- 符号链接不自动跟随；本环境相关权限用例跳过。二进制扩展不参与重排，相邻 Python 回退文件识别不代表覆盖所有原生构建方式。
- 工作区一次选择一个子项目，不保证跨子项目构建依赖；大资源不常驻内存，但 Python 源码和改写内容仍会缓存。
- 本轮只覆盖当前 12 个仓库的指定范围，不能推断其他平台、版本、种子、源码分析器或原生验证框架均兼容。测评脚本会执行上游代码，应在隔离环境运行。

## 复现边界

复现需要相同工具版本、输入及全部布局参数。当前布局版本为 4、清单 schema 为 3；不承诺复现其他工具或布局版本的输出。
