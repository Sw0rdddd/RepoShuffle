## 当前对照规则与缺口

1. 校验仓库固定提交，拒绝已修改的 tracked 文件；生成 original/shuffled 配对快照。
2. 原版与转换版使用相同配置、依赖、构建/测试命令和上游断言。没有失败节点豁免，也不改上游断言或取消检查。
3. 比较 JUnit 节点、重复次数和结果，拒绝新增、缺失、变化及新增失败。Java 报告带模块/任务目录身份；非空报告不等于证明收集了所有预期测试。
4. Python 可执行 wheel 构建、隔离安装及导入检查。Java 要求非空 JAR 类名清单且两版一致；**目前未关联迁移文件与编译产物，也不比较 class 字节或证明每个迁移文件被编译**。此缺口需修复，而不是降低“实际代码迁移”的要求。
5. 报告保留工具版本、实际 profile、日志和对照结果。`--append` 不覆盖已有项目，并检查已有结果的版本、提交和已记录的 profile。

测试和构建会执行上游代码，应使用隔离环境。使用前阅读脚本 `--help`；输出必须是新目录，追加仅限 `--append --projects ...`。

## 本地验证边界

本地仅运行工具单测、静态检查、必要受控定点工程和工具构建/安装验证，按改动范围选择。受控 Java 构建用例需要 JDK/Maven/Gradle；工具不在 PATH 时可通过 `REPOSHUFFLE_MAVEN`、`REPOSHUFFLE_GRADLE` 指定路径。跳过工具缺失用例，不算构建验证通过。

版本验证记录只写实际执行结果及其环境。后续修复的复验单独标明，不把历史通过数改写为新版本或新工作树结果；局限性与开放问题分别见[局限性](limitations.md)、[审查记录](review.md)。
